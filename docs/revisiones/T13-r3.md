Notas que no bloquean:
1. **Errores del servidor.** `order-form.tsx:183-193` también trata como «No hemos recibido respuesta» un error que sí respondió el servidor, por ejemplo un 500 o una acción que ya no existe tras un despliegue. Es seguro para D30, porque se conserva la clave. Pero el texto no es del todo exacto, y si la acción no existe el reintento seguirá fallando hasta recargar.
2. **El doble clic de `e2e/pedidos-idempotentes.spec.ts:104-138`.** El botón se desactiva en cuanto empieza el envío, así que el doble clic manda en la práctica una sola petición, y el test solo exige «al menos una». Lo que de verdad prueba D30 en ese test es la petición repetida.
3. **Limpieza de los E2E.** Puede cancelar un pedido que la misma persona cree a mano con el mismo cliente mientras corre el test. Es un riesgo aceptable con el usuario de demostración; en CI conviene un usuario E2E propio (como ya dice el plan de T10).
